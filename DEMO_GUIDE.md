# Live demo guide (about 4 minutes)

**Sinhala quick run:** PowerShell එක මේ project folder එකේ open කරලා පහළ commands එකින් එක run කරන්න. ඉන්පසු browser එකෙන් `http://127.0.0.1:8000/dashboard` යන්න. Demo data සියල්ල test data විතරයි; ඇත්තටම මුදල් යවන්න එපා.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python setup_demo.py
uvicorn main:app --reload
```

## Walkthrough

1. Show dashboard and its review counts. Open `/dashboard/upload`.
2. Select **ORD-001**, upload `demo_slips/matching_payment.png`, run OCR, then **Run demo verification**. Explain that approval is only for the fully matching *simulated* slip + SMS + order evidence.
3. Upload `demo_slips/wrong_amount.png` for **ORD-001**. Its amount differs from the order. The system should not approve; show the reason and the action for the employee/customer.
4. Upload the same matching slip again. The duplicate image hash / transaction allocation should prevent a second approval; show the previous related payment/ledger evidence or manual review outcome.
5. Upload `demo_slips/matching_payment_border.png` (after running `python create_slip_variant.py`) to show same transaction text with different image bytes. Explain that SHA-256 alone cannot identify image crops, so OCR transaction identity and the unique allocation key are also checked.
6. Upload `demo_slips/suspicious_wrong_account.png` for **ORD-001**. It claims the correct amount but names the wrong receiving account; it must not approve.
7. Upload `demo_slips/unclear_payment.png` for **ORD-001**. Its low-resolution blurred text should be sent for manual verification, not approved.
8. Upload `demo_slips/pending_sms_payment.png` for **ORD-002**. There is no corresponding seeded SMS for its transaction, so it must wait for bank evidence or manual review.
9. Explain that scenario tests exercise old/future dates, multiple SMS candidates, non-simulated evidence, conflicting/missing fields, and duplicate/reused transactions without presenting synthetic proof as a real bank confirmation.

All slips are generated by `python setup_demo.py` and contain synthetic evidence only. Keep the DEMO ONLY label visible when presenting them.
